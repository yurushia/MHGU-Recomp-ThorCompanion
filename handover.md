## The two issues and where they stand

### 1. Tapping an item must use it, not just select it: WORKING in game (confirmed by the user). Mechanism documented in docs/THOR-COMPANION.md, "How the one tap works"
- Latest report from the user: the panel says "using", the in-game item bar switches to the item, then nothing happens.
  That means the slot write (`player +0x3298`) works and the injected press is not taking effect.
- Mechanism (`runtime/hle/companion.c`): a hook on the game's pad poll `0xa6d34c` (`pad, a1, id, out`) ORs Y (`0x8000`,
  R `0x200` for a drawn Sword and Shield) into `out[0]` for up to 3 polls, once the game's own "may use an item" tests pass
  (`0x47bcd0 == 1`, `0x47b918 == 0`, vfunc `+0x230(player, 1) == 1`). Success only when the slot's count dropped or the hunter
  acted from idle; otherwise it retries (up to 4) and reports `ignored`. If the poll can't be hooked it falls back to
  `companion_buttons()` in `input.c`'s `fill_state`.
- Most likely cause found: the hook required `r2` to be a pointer to a zero id. RadialMenu's hook (the proven reference,
  `radial.c` `pad_detour`) never dereferences it. Fixed in `042b156`; a host test fails on the old code and passes on the new.
- **Not verified in game.** First test to ask for: weapon sheathed, standing still, tap a Potion. If that still fails, other
  suspects: the game ignoring the injected press (try `[Actions] Enable=0`), the hook not installing on Android (it would
  log `through GetNpadState`), the weapon-drawn branches (sheathe-then-use for non-SnS weapons is untested), double polls per frame.
- The user does not want to do diagnostics debugging. If a further blind fix is needed, compare line by line against
  RadialMenu's `step_pending` / `handle` (v0.1/v0.2 of that plugin are the only parts proven in game; its retry and use-when-chosen
  were not tested either).
- The Duo Companion does NOT depend on the Forge plugin or RadialMenu. It is built into the app. RadialMenu is only a design reference.
  Do not run both at once when testing.

### 2. Map button toggles whole map / current area: done at code level, not checked on a device
- A THIS AREA | WHOLE MAP control (or a tap on the map body) alternates the contents. Zoom/drag work in both modes.
- Root cause of the old limit: only the hunter's own area's collision files are loaded, each in its own coordinate frame, with
  no cross-area placement data. So the whole map uses the stage pictures from the user's `mhgu-maps.zip`
  (`android/assets/maps/map_NN.png`, 1024x1024, 27 stages) plus `areas.csv`.
- Markers are area-level: the hunter and each large monster sit next to their area's number. `areas.csv` is generated by
  `tools/maps/make_anchors.py` (reads the numbers off the pictures). Only maps 1 and 2 were checked visually. Map 2 has no camp icon found.
- **The 27 PNGs are Capcom artwork and are not committed** (kept out via `.git/info/exclude`). Without them the build works and
  WHOLE MAP says "no whole map for this stage". Source/rights notes: `android/assets/maps/NOTICE-maps.txt`, `THIRD_PARTY_NOTICES`.

## Building the APK
```bash
export ANDROID_HOME=/opt/android/sdk JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
make PLATFORM=android ABI=arm64-v8a -j4        # about 4 min; output build-android/mhgurecomp.apk
```
Without `ANDROID_HOME`/`JAVA_HOME` the make fails ("no Android NDK in /c/Android/Sdk" or "Unable to find package java.lang").
The APK is signed with the debug keystore (`/root/.android/debug.keystore`), the same key as the user's installed app.

## Key offsets (game v1.4.0, main at 0x200000)
- sQuest `0x1a8ad90` (`+0x1c` ticks left, `+0xcc` limit minutes); sPlayer `0x1a85b58`; sGameControl `0x1a8ca48` (`+0x4c` = 0xff in a quest).
- Player: `+0x40` pos, `+0x1054` zone, `+0x114c` weapon drawn, `+0x13d6/8/a` HP, `+0x13e0/4` stamina, `+0x2774/8` sharpness,
  `+0x3298` selected pouch slot, `+0x2506/+0x250a` action pair (idle 1:0), `+0x13cc` flags.
- Pouch `0x1a584b8`: slot n at `+0x1a+4n` (u16 id, s16 count at `+0x1c`). sEnemy `0x1a51fe0`.
- Pad poll `0xa6d34c`: engine button word Y `0x8000`, R `0x200`. NpadButton Y = bit 3, R = bit 7.
